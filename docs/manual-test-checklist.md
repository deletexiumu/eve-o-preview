# EVE-O Preview for macOS 手工测试清单

本清单对应 `docs/architecture.md` 10.3 节里需要人工操作的项目：手势、热键（含 V7 的 `opt+F13`）、悬停放大、右键菜单、菜单栏菜单、设置窗口各页、退出时写盘。
测试方于 2026 年 11 月 20 日整理。测试方只做了被动观察，没有向 EVE 客户端发送任何鼠标或键盘事件，所以以下项目都要你亲手做。

每一步做完后对照「预期」，在步骤前的方框里记录通过（`[x]`）或失败（`[!]`），失败的写下实际现象。

## 已由测试方自动验证的项目

以下项目在 2026-11-20 已验证通过，不必重做。

- 3 个真实客户端各出现一个缩略图，标题是角色名，画面持续更新，自动排位写进配置文件。
- 演示模式下登录客户端改名、缺少屏幕录制权限的占位、「用户已停止」的占位。
- 配置文件损坏时被隔离并改用默认配置；配置文件版本更新时应用照常运行，且不改写文件。
- 同时启动两个 `.app` 实例时，后启动的立即退出。
- `scripts/build-app.sh` 的产物通过 `codesign --verify --strict` 与 `plutil -lint`。
- 设置窗口（演示模式，2026-11-20 修复后）：侧栏显示 6 个页名，「客户端」「切换与热键」「关于」页从第一段开始显示，「预览与布局」页可以滚动。
- 「重新启动」的交接（演示模式，临时组装的 `.app`，2026-11-20）：带 `--relaunched-from <旧 PID>` 启动的新实例等旧实例退出后继续运行；不带这个参数的第二个实例照常退出；用 Apple Event 退出约 0.2 秒完成。

## 准备

**注意：** 用 ad-hoc 签名构建后，每次重新构建都要重新授权。宜先按 `docs/architecture.md` 9.2 节用自签名证书 `EVEO Preview Dev` 构建。

1. [ ] 运行 `SIGN_IDENTITY="EVEO Preview Dev" scripts/build-app.sh`。
   预期：最后两行打印产物路径与「签名：EVEO Preview Dev」。
2. [ ] 启动 3 个 EVE 客户端，全部用窗口模式，选好角色。
   预期：3 个客户端都停在游戏内，不在登录界面。
3. [ ] 准备一个能发出 F13 的键盘（外接全尺寸键盘，或用 Karabiner-Elements 把某个键映射成 F13）。
   预期：后面的 V7 测试能按出 `opt+F13`。没有 F13 时跳过第 V7 节，在结果里注明。

## 首次启动与权限（10.3 第 1 项）

1. [ ] 双击 `dist/EVE-O Preview.app`。
   预期：菜单栏出现本应用的图标，没有 Dock 图标；设置窗口打开在「权限」页，两项权限显示未授权。
2. [ ] 点「权限」页上屏幕录制的请求按钮，在系统设置里打开本应用的开关，再点「重新启动」。
   预期：应用重启后 3 个缩略图出现实时画面。
3. [ ] 在终端运行 `pgrep -fl EVEOPreview`，再点一次「权限」页的「重新启动」，5 秒后再运行一次。
   预期：第二次的 PID 与第一次不同，且只有一个；菜单栏只有一个本应用的图标。修复前新实例会因单实例检查退出，两个实例都消失。
4. [ ] 在系统设置里打开本应用的辅助功能开关，回到「权限」页观察。
   预期：辅助功能的状态在 1 秒内变成已授权，不需要重启。

## 发现、退出与重新登录（10.3 第 2、3 项）

**注意：** 退出客户端前，让角色停在空间站内，否则角色会留在太空中。

1. [ ] 观察屏幕左上方的缩略图。
   预期：有 3 个缩略图，标题分别是 3 个角色名；EVE 启动器没有缩略图。
2. [ ] 正常退出其中一个客户端。
   预期：对应的缩略图在 2 秒内消失，另外两个不动。
3. [ ] 重新启动这个客户端，停在登录界面。
   预期：登录界面阶段出现一个标题为 `EVE` 的缩略图，位置在登录位置（默认左上角 (5, 40) 附近）。
4. [ ] 选择原来的角色进入游戏。
   预期：2 秒内标题变成角色名，缩略图回到这个角色以前保存的位置。

## 点击切换与最小化（10.3 第 4、5 项）

1. [ ] 依次左键点击 3 个缩略图，各点一次。
   预期：每次被点的客户端都到前台。
2. [ ] 在 3 个缩略图之间连续左键点击 20 次。
   预期：20 次全部切换成功，没有一次停在原客户端。
3. [ ] 从菜单栏菜单打开「设置…」，让设置窗口留在前台，再左键点击一个缩略图。
   预期：被点的客户端到前台；设置窗口打开期间缩略图不消失。
4. [ ] 按住 Ctrl 左键点击一个缩略图。
   预期：对应客户端最小化，缩略图显示「已最小化」占位。
5. [ ] 不带修饰键左键点击这个缩略图。
   预期：窗口还原并到前台，占位消失，画面恢复更新。

## 右键菜单

1. [ ] 在一个缩略图上右键按下并松开，期间不移动鼠标。
   预期：弹出菜单，依次是「最小化」「全部最小化」「跳过循环」「隐藏此缩略图」「恢复默认尺寸」「设置…」；「恢复默认尺寸」只在这个缩略图缩放过时可用。
2. [ ] 选「跳过循环」。
   预期：缩略图右上角出现红色禁行标记。
3. [ ] 再打开同一个菜单。
   预期：「跳过循环」前有勾选标记；再选一次后标记消失。
4. [ ] 选「隐藏此缩略图」。
   预期：缩略图消失；设置窗口「客户端」页里该角色的「显示缩略图」开关变为关闭。
5. [ ] 在「客户端」页打开该角色的「显示缩略图」开关。
   预期：缩略图重新出现在原位置。

## 循环组与热键（10.3 第 6、7 项）

1. [ ] 在「切换与热键」页新建一个循环组，从在线角色依次添加 3 个角色。
   预期：成员列表按添加顺序显示 3 个角色名。
2. [ ] 给这个循环组录制前进热键 `F14` 与后退热键 `shift+F14`。
   预期：两个热键显示为 `F14` 与 `⇧F14`，旁边没有错误提示。
3. [ ] 切到任意一个客户端，按 10 次 `F14`。
   预期：前台客户端按成员顺序依次切换，到最后一个后绕回第一个。
4. [ ] 按 10 次 `shift+F14`。
   预期：按相反顺序切换并绕回。
5. [ ] 在第二个成员的缩略图右键菜单里选「跳过循环」，再按几次 `F14`。
   预期：循环跳过这个角色，只在其余两个之间切换。
6. [ ] 给一个角色录制直达热键 `ctrl+F15`，切到别的应用（如「访达」），按 `ctrl+F15`。
   预期：该角色的客户端到前台。
7. [ ] 录制一个只带 Shift 的普通键（如 `shift+A`）作为任一热键。
   预期：热键旁提示「缺少修饰键」，热键不生效，按 `shift+A` 时游戏里照常输入大写 A。
8. [ ] 在终端运行第「退出时写盘」节第 1 步的日志命令，然后按住 `F14` 约 2 秒再松开。
   预期：松开后前台停在最后一次切到的客户端，不会跳回中途经过的客户端；最小化的成员没有被中途还原。日志里被取代的切换只有调试级的「已被取代」，没有「切换失败」或「激活失败」的错误。
9. [ ] 点某个热键的录制按钮进入录制状态，不按键，直接点「访达」让设置窗口失去焦点。再回到设置窗口。
   预期：按钮已回到原来的文字，不再显示录制提示；切到任一客户端按 `F14`，循环照常工作。如果在录制状态下直接关闭设置窗口，结果相同。

## V7：只带 Option 的热键

1. [ ] 在「切换与热键」页的「全局热键」里，给「显示或隐藏全部缩略图」录制 `opt+F13`。
   预期：显示为 `⌥F13`，旁边没有错误提示，也没有注册失败的错误码。
2. [ ] 切到一个客户端，按 `opt+F13`。
   预期：全部缩略图隐藏。
3. [ ] 再按一次 `opt+F13`。
   预期：全部缩略图重新出现。
4. [ ] 把结果（能否触发）报给开发方，填进 `docs/architecture.md` 11.1 节 V7 一行。
   预期：不能触发时，开发方在 `HotkeyPlanner` 里拒绝只带 Option 的热键。

## 高亮（10.3 第 8 项）

1. [ ] 在「预览与布局」页打开「高亮活动客户端」，依次左键点击 3 个缩略图。
   预期：活动客户端的缩略图有绿色边框（`#ADFF2F`），边框随切换移动。
2. [ ] 切到别的应用（如「访达」）。
   预期：边框留在最后活动的客户端的缩略图上。
3. [ ] 在「客户端」页给一个角色设一个别的高亮颜色，再切到这个角色。
   预期：该角色活动时边框用新颜色，其他角色仍用全局颜色。

## 移动、吸附与缩放（10.3 第 9 项）

1. [ ] 在缩略图上右键按下后拖动超过 4 点。
   预期：缩略图跟着鼠标移动，松开后不弹出菜单，也不切换客户端。
2. [ ] 按住 Option 左键拖动另一个缩略图。
   预期：缩略图跟着移动，不切换客户端。
3. [ ] 拖动一个缩略图靠近另一个缩略图的边（8 点以内）。
   预期：边自动对齐，吸附后继续拖远会脱开。
4. [ ] 拖动一个缩略图靠近屏幕边缘或菜单栏下沿。
   预期：缩略图吸附到屏幕边或菜单栏下沿。
5. [ ] 按住 Shift 重复第 3 步。
   预期：不吸附，位置完全跟随鼠标。关闭「拖动时吸附」后，不按 Shift 也不吸附。
6. [ ] 从缩略图右下角 12 点范围内右键拖动。
   预期：缩略图从右下角缩放，左边与上边不动；最小 192×108、最大 960×540。
7. [ ] 按住 Shift 从右边缘缩放。
   预期：宽高比保持不变，不吸附。打开「缩放时保持宽高比」后，不按 Shift 也保持宽高比。
8. [ ] 在「预览与布局」页打开「锁定布局」，再尝试右键拖动。
   预期：缩略图不移动也不缩放；左键切换、Ctrl+点击最小化、右键菜单照常。
9. [ ] 关闭「锁定布局」，从菜单栏菜单选「退出 EVE-O Preview」，再重新启动应用。
   预期：每个缩略图的位置与尺寸与退出前相同。
10. [ ] 给「显示或隐藏全部缩略图」录制热键 `ctrl+F16`。右键拖动一个缩略图，不松开右键，用另一只手按 `ctrl+F16`，再松开右键；然后再按一次 `ctrl+F16`。
    预期：按下热键时全部缩略图隐藏，松开右键不保存位置；再次显示后，被拖的缩略图在拖动前的位置，之后的移动与缩放照常生效，不会停在某处不动。

## 悬停放大（10.3 第 10 项）

1. [ ] 在「预览与布局」页打开「鼠标悬停时放大」，「放大倍数」设为 2，「锚点」设为左上。
   预期：设置立即生效，不需要重启。
2. [ ] 把鼠标移进一个缩略图。
   预期：缩略图以左上角为固定点放大到 2 倍，不透明度变为 100%，放大期间画面继续更新。
3. [ ] 把鼠标移出。
   预期：缩略图还原到原尺寸与原透明度。
4. [ ] 把锚点改为中心，重复第 2、3 步。
   预期：放大时中心点不动。
5. [ ] 在悬停放大状态下右键拖动这个缩略图。
   预期：拖动期间缩略图不放大，按原尺寸移动。
6. [ ] 在悬停放大状态下，从放大后缩略图的右下角 12 点范围内右键拖动。
   预期：判断为缩放而不是移动：缩略图回到原尺寸后从右下角缩放；松开并移出鼠标后，保存的是缩放后的原尺寸，不是放大后的尺寸。

## 隐藏规则（10.3 第 11 项）

1. [ ] 在「预览与布局」页打开「隐藏活动客户端的缩略图」，左键点击一个缩略图。
   预期：被点的客户端到前台后，它自己的缩略图消失，其他缩略图仍在。
2. [ ] 切到别的应用（如「访达」）。
   预期：刚才消失的缩略图重新出现。
3. [ ] 关闭上一条设置，打开「离开 EVE 时隐藏缩略图」，「隐藏延迟」设为 2 秒，切到「访达」。
   预期：从切到「访达」那一刻算起约 2 秒后全部缩略图隐藏，不会提前 1 秒左右。
4. [ ] 切回任意一个客户端。
   预期：缩略图立即重新出现。
5. [ ] 从菜单栏打开设置窗口，等 5 秒。
   预期：设置窗口在前台期间缩略图不隐藏。

## 菜单栏菜单与配置方案（10.3 第 12 项）

1. [ ] 点击菜单栏图标。
   预期：菜单项依次是：显示或隐藏全部缩略图、「配置方案」子菜单、「全部最小化」、「设置…」、「退出 EVE-O Preview」；没有「恢复捕获」与「缺少权限，点此查看…」。
2. [ ] 选「隐藏全部缩略图」，再打开菜单。
   预期：全部缩略图隐藏，菜单项文字变成「显示全部缩略图」；选它后缩略图恢复。
3. [ ] 选「全部最小化」。
   预期：3 个客户端都最小化，缩略图都显示「已最小化」占位。
4. [ ] 在「配置方案」页新建第二个配置方案，切换过去，把 3 个缩略图拖到屏幕右侧。
   预期：新配置方案里缩略图位置是新的。
5. [ ] 在菜单栏的「配置方案」子菜单里来回切换两个配置方案。
   预期：两套布局各自保持；切换后跳过标记被清空。
6. [ ] 在系统菜单栏的录制指示器里停止本应用的屏幕录制。
   预期：缩略图显示「捕获已停止，右键菜单可恢复」；菜单栏菜单多出「恢复捕获：<角色名>」，选它后画面恢复。

## 设置窗口各页

测试方在 2026-11-20 用 `screencapture -l` 截取设置窗口（演示模式，共 4 次）时看到：侧栏的 6 个页名都没有显示；内容区有时全空，有时只显示页面最后一段，页面开头被截掉，像是内容整体向上偏移。这可能是界面缺陷，也可能只是截图方式造成的，请人工确认。

1. [ ] 从菜单栏打开「设置…」，依次点侧栏的 6 页：客户端、预览与布局、切换与热键、配置方案、权限、关于。
   预期：侧栏显示 6 个页名；每页从第一段开始完整显示，可以滚动到最后一段；窗口打开时位于前台并能接收键盘输入。
2. [ ] 在「预览与布局」页拖动透明度滑块。
   预期：缩略图的透明度随滑块实时变化。
3. [ ] 在「配置方案」页点「在访达中显示」。
   预期：访达打开 `~/Library/Application Support/EVE-O Preview/` 并选中 `config.json`。
4. [ ] 打开「关于」页。
   预期：显示版本、上游项目与 GPL-3.0 许可证、EVE 知识产权声明，以及「只切换窗口焦点，不向多个客户端广播输入」的说明。

## 退出时写盘

设置改动后 0.5 秒才写盘；从菜单退出时应立即再写一次，不丢最后的改动。退出时会多出一条「配置已保存」日志，用它判断这次写盘。

1. [ ] 在终端运行 `/usr/bin/log stream --level debug --predicate 'subsystem == "io.github.deletexiumu.eveopreview-macos"'`，保持窗口打开。
   预期：终端开始输出本应用的日志。
2. [ ] 在「预览与布局」页切换一次「缩略图置顶」开关，等 2 秒。
   预期：日志里出现一条「配置已保存」。
3. [ ] 从菜单栏菜单选「退出 EVE-O Preview」。
   预期：日志里紧接着再出现一条「配置已保存」；应用在 2 秒内退出，菜单栏图标消失。
4. [ ] 重新启动应用，打开「预览与布局」页。
   预期：「缩略图置顶」开关是第 2 步改后的状态。

## 空间、显示器缩放与能耗（10.3 第 13、14 项）

1. [ ] 把一个客户端移到另一个桌面空间，观察 1 分钟。
   预期：记录该缩略图的画面是否继续更新（V4）；不更新时应保留最后一帧，不应变黑。
2. [ ] 在一个缩略图的系统录制指示器里停止它的捕获，然后从苹果菜单选「睡眠」，1 分钟后唤醒并登录。
   预期：其他缩略图在 5 秒内恢复更新；被停止的那个仍显示「已停止」占位，不会自己恢复。日志里有一条「系统唤醒，重建捕获会话」。
3. [ ] 在「系统设置 > 显示器」里改一次缩放，观察 1 分钟。
   预期：缩略图仍在屏幕内，画面继续更新、没有变模糊。
4. [ ] 让 3 个客户端运行 10 分钟，在「活动监视器」里记录本应用的 CPU 占用与「能耗影响」。
   预期：记下数值。测试方在 2026-11-20 用 `ps` 测得 65 秒内 CPU 1.9%～4.3%、内存 69 MB～74 MB（本机 Apple Silicon、macOS 27，调试版，3 个客户端，15 帧每秒），可作对照。

## 第一轮反馈：边框、语言、鼠标热键、作用范围、战斗提醒

以下各项来自 `docs/design-feedback-round1.md` 10.2 节，2026-11-20 集成时追加。第 3、5 组要用户亲手操作鼠标或让角色受击。

第 1 组，边框：

1. 用 v1 留下的配置文件启动。预期：每个缩略图都有一圈浅灰色边框。
2. 打开高亮，切换活动客户端。预期：活动客户端显示高亮颜色的边框，其余仍是浅灰色。
3. 在「预览与布局」页关掉边框，再改颜色与粗细后打开。预期：改动立即生效，重启后保持。

第 2 组，语言：

1. 用没有 `language` 键的配置文件启动（系统语言是中文）。预期：界面是英文。
2. 在「通用」页依次选 5 种语言和「跟随系统」。预期：设置窗口的各页、窗口标题、菜单栏菜单、缩略图右键菜单、占位文字都立即变成所选语言，不用重启。
3. 每种语言下把 8 页各看一遍。预期：没有被截断或重叠的文字，没有漏翻成别的语言的文字。记录俄文下过长的条目。
4. 重启应用。预期：语言保持。

第 3 组，鼠标热键（要用户配合）：

1. 运行 `swift run EVEOProbe mousetap 20`，20 秒内按中键与两个侧键。预期：每次按下打印一行，如「按下 按钮号 3（Mouse4）」；记下每个按键的按钮号，与设计文档 6.1 节的表核对（V10）。探针只打印、不拦截。
2. 在循环组的前进热键里录制一个侧键。预期：显示为 `Mouse4` 或 `Mouse5`，作用范围默认是「仅游戏内」。
3. 在 EVE 客户端里按这个侧键 10 次。预期：每次都切到下一个客户端；游戏内绑在这个侧键上的功能不触发（V11）。
4. 在浏览器里按这个侧键。预期：浏览器照常后退，客户端不切换。
5. 把这条热键改成「全局」，在浏览器里按。预期：客户端切换，浏览器不后退。
6. 录制 `ctrl+中键`。预期：单按中键不触发并照常传给前台应用；按住 Ctrl 按中键触发。
7. 在系统设置里撤销辅助功能权限。预期：2 秒内鼠标热键旁出现「需要辅助功能权限」，键盘热键照常；重新授权后鼠标热键恢复，不用重启。
8. 按住已绑定的侧键移动鼠标再松开。预期：只触发一次，游戏没有收到这次点击与拖动。

第 4 组，作用范围：

1. 绑定一个作用范围是「仅游戏内」的键盘热键（如 `F13`）。在文本编辑器里按它对应的键。预期：按键照常输入或没有反应，客户端不切换。
2. 切到 EVE 客户端后按它。预期：切换；游戏没有收到这个按键。
3. 用菜单栏菜单的「热键只在 EVE 内生效」切换默认范围。预期：没有后缀的热键跟着变，带后缀的不变。
4. 打开设置窗口，在文本框里按一个「仅游戏内」的热键。预期：不触发。
5. 同一个按键绑两次，范围不同。预期：后一条显示重复提示。

第 5 组，战斗提醒（要用户配合，在安全的场景里让角色受到攻击）：

1. 在「提醒」页打开开关。预期：系统弹出访问「文稿」文件夹的提示（V12）；允许后状态行显示「监视中」与跟踪的文件数。
2. 点「测试闪烁」。预期：全部缩略图（含活动客户端）按设定的颜色闪烁，到时间后停止。
3. 让一个角色受到 NPC 攻击。预期：只有这个角色的缩略图闪烁；记录从游戏内受击到开始闪烁的延迟（V13）。
4. 持续受击 30 秒。预期：闪烁不间断，相位不跳；停火后在设定的持续时间内停止。
5. 该角色是活动客户端时受击。预期：它的缩略图同样闪烁。
6. 打开「离开 EVE 时隐藏」，切到别的应用，让角色受击。预期：这个角色的缩略图出现并闪烁，提醒结束后隐藏。
7. 启动应用前已有的日志内容。预期：启动后不因历史内容闪烁。
8. 让一个角色退出再登录（产生新的日志文件）。预期：新文件被跟踪，受击时照常闪烁。
9. 3 个客户端同时战斗 5 分钟，在「活动监视器」里记录本应用的 CPU 占用，与关闭战斗提醒时对比。预期：记下两个数值。
10. 在系统设置里撤销「文稿」文件夹的访问。预期：状态行显示没有访问权限，「打开系统设置」按钮可用；重新授权后 10 秒内恢复，撤销前已经提醒过的受击不会再闪一次。
11. 系统打开「减弱动态效果」后点「测试闪烁」。预期：提醒层静止显示，不闪。
12. 把日志目录改成一个不存在的路径。预期：状态行显示找不到目录；点「使用自动位置」后恢复。

第 3 组的补充（V9、V11 的直接核对）：

- 只凭辅助功能权限能否建立鼠标事件监听（V9）：在「系统设置 > 隐私与安全性 > 输入监控」里关掉终端的开关，运行 `swift run EVEOProbe mousetap 5`，再把开关打开。预期：输出里有「事件监听：已建成，tapIsEnabled = true」时，说明只要辅助功能权限就够。
- 吞掉侧键（V11）：让 EVE 位于前台、游戏里给侧键绑一个动作，运行 `swift run EVEOProbe mousetap 30 --swallow 3`（`--swallow` 后面是按钮号，等于 `Mouse` 后的数字减 1：3 是 `Mouse4`，4 是 `Mouse5`，2 是中键）。按这个侧键，也试按住拖动再松开。预期：游戏没有反应，探针在按下、拖动、松开时都打印「→ 吞掉」；按另一个侧键时游戏照常响应。
- 设置窗口里能否录到侧键（V16）：运行 `EVEO_FAKE=1 EVEO_CONFIG_PATH="$TMPDIR/eveo/cfg.json" EVEO_SETTINGS_PAGE=switching swift run EVEOPreview`，新建循环组，点「+ 添加」，鼠标停在窗口内按侧键。预期：显示 `Mouse4` 并带手柄图标，配置文件里写入 `"Mouse4@game"`。

第 5 组的补充：

- 缩略图隐藏期间收到提醒（V14）：打开「离开 EVE 时隐藏」，切到别的应用后让角色受击。预期：缩略图出现时就在闪烁，不是静止的。

### 测试方补充（2026-11-20）

## v1.1：日志、问题报告与更新

设计见 [design-v1.1.md](design-v1.1.md) 14.2 节，各组原文照搬。第 5 组要先退出正在运行的应用。

### 第 1 组：日志

1. 启动应用后看 `~/Library/Logs/EVE-O Preview/`。预期：有 `eve-o-preview.log`，第一行是会话头，目录权限 0700，文件权限 0600。
2. 让一个角色登录后在文件里搜它的名字。预期：搜不到，相应位置是 `<private>`。
3. 在「通用」页打开「详细日志」。预期：文件里立即出现 `DEBUG` 行；关掉后不再出现。
4. 用 `EVEO_LOG_DIR` 指向一个临时目录，把上限临时改小后写满。预期：出现 `.1`～`.4`，不出现 `.5`。
5. 运行 `log stream --predicate 'subsystem == "io.github.deletexiumu.eveopreview-macos"'`。预期：系统日志照常有输出。

### 第 2 组：异常退出

1. 正常退出再启动。预期：日志里上一次运行记为 `clean`，没有任何提示。
2. `kill <PID>` 后启动。预期：同上（走了正常的退出流程）。
3. `kill -9 <PID>` 后启动。预期：记为 `abnormal`，没有提示，没有圆点。
4. `kill -SEGV <PID>` 后启动。预期：约 5 秒～30 秒后菜单栏图标出现圆点，菜单顶部有报告项；前台不是 EVE 时报告窗口出现且不抢焦点（V17、V18、V27）。
5. 接上一项，前台是 EVE 客户端时启动。预期：窗口不出现；切到别的应用后出现。
6. 在窗口里选「不报告」后重启。预期：不再提示。
7. 在权限页点「重新启动」。预期：新实例记上一次为 `clean`。

### 第 3 组：问题报告

1. 从菜单打开「报告问题…」。预期：窗口列出摘要、设置摘要、日志；此时 `Reports/` 目录里没有新文件。
2. 逐个查看预览。预期：没有用户名、电脑名称、角色名；路径显示为 `/Users/[user]/…`。
3. 点「生成报告并打开 GitHub」。预期：访达选中 zip；浏览器打开新建 Issue 的页面，标题与正文已填好（V19）。
4. 解开 zip，用 `grep -ri` 搜用户名、电脑名称和每个角色名。预期：都搜不到。
5. 取消勾选日志后生成。预期：zip 里没有 `logs/`，`manifest.json` 与实际文件一致。
6. 连续生成 4 次。预期：`Reports/` 里只有最新的 3 个。
7. 5 种语言下各看一遍窗口。预期：没有被截断的文字。

### 第 4 组：更新检查

1. 用 1.1.0 的正式构建启动并等 10 秒。预期：日志里有一次检查；`state.json` 里有 `lastCheckAt` 与 `etag`。
2. 1 小时内重启。预期：不再请求。
3. 点「检查更新…」。预期：显示「已是最新版本」或更新窗口。
4. 关掉「自动检查更新」后重启。预期：没有请求；「检查更新…」仍可用。
5. 断网后点「检查更新…」。预期：显示网络错误，应用照常运行。
6. 用 ad-hoc 构建、开发证书构建各做一次第 3 项（用测试地址提供一个更新的版本）。预期：ad-hoc 显示原因与「打开发布页」；开发证书在正式地址下只提示。
7. 直接从 dmg 里打开应用。预期：窗口说明应用在只读磁盘上。

### 第 5 组：本地端到端安装（要用户配合；先退出正在运行的应用）

1. 用 `SIGN_IDENTITY="EVEO Preview Dev"` 构建 `VERSION=1.1.0` 的应用 A，拷贝到 `~/Applications/`。从访达打开 A，给它授予屏幕录制与辅助功能权限，确认缩略图有画面，然后退出。再构建并打包 `VERSION=1.1.1` 的应用 B，得到 dmg 与 `SHA256SUMS.txt`。
2. 写 `feed.json`（`tag_name` 是 `v1.1.1`，附件地址指向 `http://127.0.0.1:8123/`），在 `dist/release/` 下运行 `python3 -m http.server 8123 --bind 127.0.0.1`。
3. 运行 `open --env EVEO_UPDATE_FEED_URL=http://127.0.0.1:8123/feed.json "$HOME/Applications/EVE-O Preview.app"`。不直接运行包里的可执行文件：那样权限记在终端名下（架构文档 9.2 节）。第 4 项就比不出权限是否保留。预期：出现更新窗口，带「测试地址」字样，发布说明按界面语言显示（V20）。
4. 点「安装更新」。预期：进度依次是下载、核对、安装、重新启动；新实例的「关于」页显示 1.1.1；不用重新授权，缩略图有画面，最小化可用（V22、V23）。
5. 改 dmg 的一个字节后重做。预期：报校验和不符，A 没有变化。
6. 把 B 改用 ad-hoc 签名后重新打包（校验和文件随之更新）再重做。预期：报无法验证，A 没有变化，`codesign --verify` 对 A 仍通过。
7. 把 `feed.json` 的版本改成 `v1.2.0`，附件仍是 1.1.1 的 dmg。预期：报版本不符，A 没有变化。
8. 下载途中停掉 HTTP 服务。预期：报网络错误，缓存目录里没有 `.partial` 文件。
9. 打开「自动安装更新」，用测试地址启动 A。预期：不出现窗口；菜单出现「重新启动以更新到 1.1.1」；退出应用后再打开是 1.1.1。
10. 把 A 所在的文件夹改成只读后启动。预期：窗口说明没有权限，只有「打开发布页」。

  5. 把应用 A 放在 `/Applications`（不是 `~/Applications`），从访达打开，再按第 5 组第 2～4 项做一次安装。预期：替换成功，权限保留；若系统阻止修改 `/Applications` 里的应用，报替换失败，A 不变（审查 M3）。
  6. 把应用 A 放在一个 HFS+ 或 exFAT 格式的磁盘映像里运行，点「安装更新」。预期：报替换失败或只提示，A 不变。
